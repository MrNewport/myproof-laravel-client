# Package-only release checklist

This checklist describes the MIT source-to-release boundary. The monorepo uses an adjacent development dependency; a standalone export selects a stable evidence constraint. Repository tags and release records establish publication. No Packagist listing is assumed.

1. Review the exact SDK commit and `release-manifest.json`. Publish and verify the compatible independent MIT `MrNewport/myproof-evidence` v1.0.0 tag first. The evidence package supplies the closed event/source and webhook canonicalization contracts used by this SDK; do not replace that exercised dependency with a second validator.
2. From a clean committed application branch, run `php packages/laravel-client/build-release.php /absolute/new/output-directory`. The source-tree builder accepts only the manifest's exact committed file list and rejects dirty, unexpected or symlink entries. It strips the development adjacent path repository and changes `myproof/evidence` to `^1.0` in the exported Composer manifest, recording source/release SHA-256 and byte lengths in `SOURCE-PROVENANCE.json`. The export contains no private application's Git history, remotes, environment, operator reports, databases, logs, provider identifiers, infrastructure or deployment configuration. Do not hand-edit a second copy of the SDK to prepare the release.
3. Run `composer validate --strict`, a clean `composer install`, tests and dependency audit from a copy of the isolated output. If evidence is not on Packagist, the **consumer root** must explicitly add the public `https://github.com/MrNewport/myproof-evidence` VCS repository; a repository entry in a dependency's manifest is ignored by Composer consumers. The standalone CI sets that public VCS repository and tests PHP 8.3/8.4 with Laravel 12/Testbench 10 and Laravel 13/Testbench 11. Its installed-consumer smoke uses an SDK path repository only for the candidate package under test; no application source is present.
4. Inspect the complete output file list, provenance hashes, dependency manifests and documentation links. Verify there are no symlinks escaping the package, private values or links into the private application. `README.md` and this document must remain usable without the application checkout. Verify source filtering, collection-part and webhook fixtures on both Laravel majors. Run application consumer checks separately; transport doubles are not live provider acceptance.
5. Only the release owner may initialize a new public Git repository, publish reviewed tags and register the public package. Publication is a separate action. Do not use a push that can include the private application's refs or history. Record the exact released commit/tag and clean consumer results after that action succeeds. Until the evidence v1.0.0 tag exists, a local `1.0.0` path override may exercise the candidate's code but cannot establish public dependency resolution or release readiness.

## Responsibility audit

The portfolio package audit was reread. `mrnewport/laravel-plaid` source (`PlaidClient`, DTOs, provider) and its transport tests were inspected; the current GitHub release was checked as [v2.0.0](https://github.com/MrNewport/laravel-plaid/releases/tag/v2.0.0). Its reusable contract is a Plaid client with Plaid credentials, endpoints and exceptions, not a configurable generic bearer API SDK. Installing it here would introduce unused Plaid responsibilities. This client continues using the existing Laravel HTTP/Guzzle transport and actually calls the shared `myproof/evidence` source/canonical/schema validator in the event filter and webhook verification paths. No portfolio package adoption is claimed from a manifest alone.

## Current machine API boundary

The implemented client follows fixed `/api/v1` routes; it has no arbitrary request or path escape method. Account, billing, integrations, token administration, full-private exports and browser-session-only operations are not exposed by this credential. Custom-domain claim and status methods use the explicitly approved owner-only API contract; writes require an independently short browser-confirmation grant. DNS changes, retry and removal remain explicit browser/operator actions.
